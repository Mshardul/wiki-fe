# Heap Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the generic Heap (tree) shape, the Heap visualizer with five variants, and heap sort as the eighth Sorting algorithm, all driven by one shared heap engine.

**Architecture:** `lib/visualizer/heap/engine.ts` produces pure `HeapEvent[]` runs (insert, extract, build, heap sort) on `{ value, tag? }` items; `heap/view.ts` turns an event into one `HeapModel` that draws the tree with the array (bars with level bands) underneath it as a single picture. The Heap module and Sorting's heap sort are two thin adapters over the same events. Tree position maths is generic (`core/tree.ts`) so a later BST or segment tree can reuse it.

**Tech Stack:** Next.js App Router, React, TypeScript, Vitest + Testing Library, pnpm, plain CSS with `--viz-*` tokens.

**Spec:** `docs/superpowers/specs/2026-11-14-backlog-visualizers-design.md` (Heap shape, per-visualizer table, stage layout). Built on the shipped Sorting work (`docs/superpowers/plans/2026-11-14-fit-to-stage-and-sorting.md`). Read `docs/_meta/visualizer/README.md` and CONVENTIONS.md § Visualizer and § CSS first.

## Global Constraints

- Generic code (`components/visualizer/**`, `lib/visualizer/core/**`) uses structural words only (tree, node, level, parent); heap words (sift, root-out, top-K) live under `lib/visualizer/heap/`.
- The Heap shape scales uniformly (tree and array together) to the stage size it receives via `useFitScale`; there is no second block. Maths lines and counters go to frame `vars` and the corner metric; the colour legend is dropped.
- Colours only via `--viz-*` tokens; new sizes become tokens in `css/tokens.css`; breakpoints only in `css/responsive.css`; nothing may break at 320px.
- Colour language: green done or placed, amber waiting, indigo the node being moved, white ring the node it is compared with, grey untouched. The tree node and its array bar always carry the same tone, so both light up in sync.
- Frames are pure and deterministic from inputs. Every change gets its own step; a step never skips a change; no two adjacent frames have identical models.
- Comments and docstrings are one line. No ticket IDs in code or CSS. No `console.*`.
- Tests are written together with the code (fixture-first, hand-checked values below). Run the whole suite once at the end (Task 8), not per step.
- No git steps anywhere; the user owns version control.
- Step copy is plain English, 2–4 loop lines per variant, never source code. Each variant picks its own learning-first defaults; the shared default sequence is `5,3,8,1,4,7`.
- Sorting's heap sort is a max-heap sorting ascending; the Heap visualizer honours its min/max toggle.

## Review Focus

- All-equal and duplicate values: ties never swap, every variant still ends on "Done" with no repeated frame; heap sort with Stability on visibly reorders equal items.
- Two-value and three-value inputs, and Top-K with k at or above the value count: no missing-child or empty-heap errors.
- A custom sequence with junk or too few numbers falls back to the default; k clamps to 2–5; a URL frame index past the new run's length falls back to the first step.
- A 12-node tree with its array at 320px shrinks to fit the stage, the page never scrolls sideways, the figure grows when both side panels collapse, and node positions never shift between frames while the heap grows or shrinks.
- Heap sort's last frame: empty tree, whole array green, "Done"; the Revision card for it still shows tree and array.

### Task 4: Heap engine, maths and view

**Files:** Create under `lib/visualizer/heap/`: `engine.ts`, `maths.ts`, `view.ts`; tests `engine.test.ts`, `maths.test.ts`, `view.test.ts`.

**Interfaces:**
- `engine.ts`: `type Order = "min" | "max"`; `interface HeapItem { value: number; tag?: string }`; `type HeapBadge = "Start" | "Add" | "Pick child" | "Compare" | "Swap" | "In place" | "Take root" | "Move last" | "Heap built" | "Swap root" | "Done"`; `interface HeapEvent { badge: HeapBadge; caption: Rich; items: HeapItem[]; size: number; sortedFrom: number; node: number | null; other: number | null; leaving: HeapItem | null; taken: HeapItem[]; comparisons: number; swaps: number }` (`items` is the whole backing array, indexes from `sortedFrom` are final heap-sort output, `sortedFrom` equals `items.length` when none); `beats(order: Order, a: HeapItem, b: HeapItem): boolean` (strict, so ties never swap); `insertRun`, `extractRun`, `buildRun`, `heapsortRun`, each `(items: HeapItem[], order: Order) => HeapEvent[]`; `insertCost(items: HeapItem[], order: Order): { comparisons: number; swaps: number }`.
- `maths.ts`: `parentLine(i: number): string`; `childLine(i: number, size: number): string`.
- `view.ts`: `heapModelOf(ev: HeapEvent, capacity: number): HeapModel` (its `array` is built here: row 0 is the heap array with level-band zones `L0, L1, …` over `0..size-1`, a green "sorted" zone over `sortedFrom..end`, and a second row labelled "taken out" when `taken` is non-empty); `mathsVarsOf(ev: HeapEvent): VarRow[]` (the parent or child line for the node in play, for the Step tab). One tone function feeds both models: `node` indigo, `other` white ring, indexes at or past `sortedFrom` green, else grey.

**Run grammar:** First badge "Start", last "Done". Insert: per value one "Add", then sift-up as `Compare`, then `Swap` or `In place` (no step once at the root). Extract starts from a silently built heap: `Take root` (slot empties, `leaving` set, item goes to `taken`), `Move last` (last item to the root, size shrinks), then sift-down as `Pick child` (only with two children), `Compare` with the chosen child, `Swap` or `In place`. Build sifts down from the last parent to the root with the same three steps. Heap sort is Build, one `Heap built`, then per remaining item `Swap root` (root and last swap, last turns final) followed by sift-down on the shrunk heap. Comparisons count `Pick child` and `Compare`; swaps count `Swap` and `Swap root`.

### Task 5: Top-K run

**Files:** Create `lib/visualizer/heap/topk.ts`; test `topk.test.ts`.

**Interfaces:**
- Consumes: `HeapItem`, `Order`, `beats` from `engine.ts`.
- Produces: `type TopKBadge = "Start" | "Read" | "Add" | "Check root" | "Skip" | "Evict" | "Place" | "Pick child" | "Compare" | "Swap" | "In place" | "Done"`; `interface TopKEvent { badge: TopKBadge; caption: Rich; heap: HeapItem[]; stream: HeapItem[]; reading: HeapItem | null; skipped: HeapItem | null; leaving: HeapItem | null; node: number | null; other: number | null; comparisons: number; evictions: number }` (`stream` is what is still unread); `topKRun(items: HeapItem[], k: number, order: Order): TopKEvent[]`. Min order keeps the K largest, max order keeps the K smallest; a value replaces the root only when it beats the root's opposite, so equal values are skipped.
