# Hash Table Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the generic Table shape (a vertical slot list) and the Hash Table visualizer with five variants (Chaining, Linear probing, Quadratic probing, Double hashing, Resize), each with a looping Revision card.

**Architecture:** Three pure engines under `lib/visualizer/hash-table/` (open addressing with markers, chaining, resize built on linear probing) turn operations into events: the whole table after each step plus the key in hand, the slots probed so far and the count. `view.ts` turns one event into one `TableModel`; the module is a thin adapter. The Table shape knows only slots, items hanging off a slot, arcs between slots, a held chip with a dashed pointer, runs and a meter; every hash word lives under `lib/visualizer/hash-table/`. Data Partitioning later reuses Table for its directory and its score table.

**Tech Stack:** Next.js App Router, React, TypeScript, Vitest + Testing Library, pnpm, plain CSS with `--viz-*` tokens.

**Spec:** `docs/superpowers/specs/2026-11-14-backlog-visualizers-design.md` (Table shape, per-visualizer table, stage layout). Read `docs/_meta/visualizer/README.md` and CONVENTIONS.md § Visualizer and § CSS first. Pattern: `2026-11-14-split-stage-and-sorting.md` and `2026-11-14-heap.md`, both already built (`useFitScale`, `FitBox`, `ArrayShape`, `HeapShape`, `core/array-model.ts` exist).

**Prerequisite:** none for Part A (new files only). Part B edits shared files that the Graph plan (`2026-11-14-graph-traversals.md`) also edits; see "Shared files" below.

## Global Constraints

- Generic code (`components/visualizer/**`, `lib/visualizer/core/**`) uses structural words only (slot, item, arc, run, chip, meter); hash words (key, probe, marker, tombstone, chain, load factor, rehash) live under `lib/visualizer/hash-table/`.
- The stage holds ONE picture that fills it and scales uniformly with it (`FitBox` / `fitScale`, capped at `--viz-fit-scale-max`); no right-hand block. Counters go to the corner metric and frame `vars`; there is no colour legend (compare modules have none).
- Table is a VERTICAL slot list, slots `0..m-1` with the index on the left, drawn at natural size and scaled to fit the stage like every new shape.
- Open addressing: filled, empty and marker slots, an arc from the home slot to each probed slot labelled with its offset, a dashed amber outline over each run of three or more occupied slots (cluster). Chaining: a short slot cell with items growing to the right, visited items outlined. The key in hand is a chip with a dashed line to its home slot.
- Colour language: green placed or found, amber probed and taken (the key is still waiting), indigo the current item (the chip, the home slot, the old slot being moved), white ring the slot or item being probed now, grey untouched. Colours only via `--viz-*` tokens; new sizes become tokens in `css/tokens.css`; breakpoints only in `css/responsive.css`; nothing breaks at 320px.
- Every change gets its own step: a hash, a probe, a hop, a placement, a marker, an unlink, a grow, a rehash move, the switch. No step skips a change; no two adjacent frames have identical models. The scan past an empty old slot during rehash is not a change and has no step. First badge "Start", last badge "Done". All five variants set `restartOnSwitch`.
- Hash is `key mod size`; the second hash is `1 + key mod 7`. Keys are whole numbers 0..99 (0 is a valid key). A probe walk makes at most `size` probes.
- Frames are pure and deterministic from the inputs and seed. Comments and docstrings are one line. No ticket IDs in code or CSS. No `console.*`. Step copy is plain English, 2–4 loop lines per variant, never source code.
- Tests are written with the code against the hand-checked fixtures below. Run the whole suite once at the end (Task 8), not per step. No git steps anywhere; the user owns version control.

## Readout placement (decided per item; no right block)

| Item | Goes | Why |
|---|---|---|
| Hash maths (`32 mod 8 = 0`) | inside the picture, as lines under the chip's key | It is the reason the dashed line lands where it does; the Step tab can be collapsed (the right panel starts collapsed under 1200px). |
| Second hash (`1 + 32 mod 7 = 5`) | a second line on the chip; the arcs carry the offsets `+5 +10 +15` | The step is the whole point of double hashing and must be visible next to the arcs it explains. |
| Jump rule (`+1 +4 +9`) | arc labels, the offset from the home slot | The student sees the jump pattern where it happens. |
| Probe count / nodes walked | corner metric, plus `vars` row `probe` | It is the one main counter; the arcs and outlines already show the path. |
| Load factor | `vars` row `load` (`7 / 8 = 0.88`) and a meter strip in the picture | The meter shows the fill; the arithmetic is a counter. The threshold mark is drawn only in Resize, where crossing it is the event. |
| Cluster length | no number; the dashed amber outline only | The outline is the lesson. |

## Fixtures (hand-checked and re-run in a script; used by the engine, view and module tests)

Size 8, `hash = key mod 8`. "Fixture table" means a preloaded table passed to the engine: slots `[16, 8, 24, _, _, 5, _, _]` (16 at slot 0, 8 at 1 after a probe, 24 at 2 after probes, 5 at 5). Event lists show badges; `@n` is the slot; counts include Start and Done.

- **Linear, insert 32 on the fixture table (11 events):** `Start, Hash, Probe@0, Hop, Probe@1, Hop, Probe@2, Hop, Probe@3, Place@3, Done`. Probes 0, 1, 2 are taken, 3 is empty, 4 probes, arcs `+1 +2 +3`, final `[16,8,24,32,_,5,_,_]`, one run 0..3.
- **Chaining, insert 32 on `[16,8,24]` at slot 0 and 5 at slot 5 (7 events):** `Start, Hash, Walk, Walk, Walk, Place, Done`; chain at slot 0 goes 16 → 8 → 24 → 32, walked 3 nodes. The same table then `delete 8`: `Hash, Walk, Walk, Found, Unlink`, chain 16 → 24 → 32; then `lookup 24`: `Hash, Walk, Walk, Found`, walked 2. Delete of a missing key 99 on an empty slot 3: `Hash, Not found`.
- **Quadratic, insert 32 on the fixture table (9 events):** `Start, Hash, Probe@0, Hop, Probe@1, Hop, Probe@4, Place@4, Done`; arcs `+1 +4`; slot 2 is never tried, 3 probes. The table is preloaded because quadratic probing cannot build it: 24 itself lands at slot 4 (0, 1, then 0 + 2² = 4). On the table built by `16,8,24` plus 32 the walk is slots `0,1,4,1,0,1,4,1` (eight probes, arcs `+1 +4 +9 +16 +25 +36 +49`), then `Stuck`, with slots 2, 3, 5, 6, 7 free and unreached (34 events for `16,8,24,32` from empty).
- **Double hashing, second hash `1 + key mod 7`, insert 32 on the fixture table (11 events):** second hash `1 + 4 = 5`; `Start, Hash, Probe@0, Hop, Probe@5, Hop, Probe@2, Hop, Probe@7, Place@7, Done`; slots 0, 5, 2 taken, 7 empty, 4 probes, arcs `+5 +10 +15`. Building from empty with `16,8,24,5,32` gives the same four probes (27 events) and final `[16,_,8,_,24,5,_,32]`. A cycle without a free slot: size 7, keys `6` then `13` (both have second hash 7, which is 0 mod 7): the second insert probes slot 6 seven times, then `Stuck`.
- **Marker:** on the fixture table `delete 8`: `Hash, Probe@0, Hop, Probe@1, Found, Mark`, slot 1 becomes a marker. Then `lookup 24`: `Hash, Probe@0, Hop, Probe@1, Hop, Probe@2, Found`, 3 probes, the marker at 1 is stepped over (15 events for both). After the delete, `insert 32`: probes 0, 1 (marker, remembered), 2, 3 (empty), then `Place@1` reuses the marker, 4 probes, final `[16,32,24,_,_,5,_,_]` (17 events).
- **Resize, size 8, threshold 0.75, keys `16,8,24,5,32,13,21` (70 events), open addressing with linear probing:** load is `(full + marker slots) / size` and a resize starts after an insert places a key and the load is strictly above the threshold. After 13 the load is 6/8 = 0.75, not above. After 21 it is 7/8 = 0.875, so the 7th insert triggers it. Before: `[16,8,24,32,_,5,13,21]`. `Grow` makes size 16 (twice 8); the old table fades. Rehash order is old slot order, empty slots skipped: 16, 8, 24, 32, 5, 13, 21. Each is a `Move` (the chip shows `key mod 16`) then probes in the new table: 16 → 0; 8 → 8; 24 → 8 taken, 9; 32 → 0 taken, 1; 5 → 5; 13 → 13; 21 → 5 taken, 6. New table `[16,32,_,_,_,5,21,_,8,24,_,_,_,13,_,_]` (load 7/16 = 0.44). Then `Switch` (old table gone) and `Done`. Badges: the 39 steps of seven inserts, `Grow`, 27 steps of rehash, `Switch`, `Done`. Mini card: size 4, keys `5,9,2,6` triggers on the 4th insert (4/4 = 1 above 0.75), grows to 8, rehash order 6, 5, 9, 2, final `[_,9,2,_,_,5,6,_]` (36 events).
- **Defaults (hand-picked per variant, 8 slots):** chaining and linear `16,8,24,5,32` (18 and 29 events); quadratic `16,8,24,5,13` (25 events: 24 shows the jumps +1 then +4, final `[16,8,_,_,24,5,13,_]`); double `16,8,24,5,32` (27 events); resize `16,8,24,5,32,13,21` (70 events).
- **Edge runs:** duplicate: insert 8 on the fixture table is `Start, Hash, Probe@0, Hop, Probe@1, Found, Done` (nothing stored twice). Key 0: `insert 0` goes to slot 0 (`0 mod 8 = 0`), then `insert 8` probes 0 and 1 and lands at 1. Size 1: `insert 5` places at slot 0; `insert 6` is `Hash, Probe@0, Stuck`. Full: size 4, keys `0,1,2,3,4` gives four probes for key 4 (slots 0..3) then `Stuck`. Delete of a missing key 99 on the fixture table: `Hash, Probe@3, Not found`.

## Review Focus

- Full table with no free slot (size 4, keys `0,1,2,3,4`; size 1, second insert): the walk ends on `Stuck` after at most `size` probes, never loops, nothing is placed, and the run still ends on `Done`. The Resize variant never reaches it because it grows first.
- Probing cycle that never finds a free slot although slots are free (quadratic `16,8,24,32` at size 8; double hashing size 7 keys `6,13`): `Stuck` after exactly `size` probes with the repeated probes shown, and a caption that says free slots exist.
- Duplicate key (insert 8 twice, or the same key in chaining): `Found`, no second copy, no placement. Key 0 is stored and found (no falsy check). Delete or lookup of a missing key ends on `Not found` with the table unchanged; chaining deletes a middle node by relinking.
- Table size 1 (engine) and the field clamp 4–12 (module): size 1 never divides by zero, the second hash and every mod work, quadratic and double probe slot 0 repeatedly then `Stuck`.
- Markers: lookup steps over a marker; insert remembers the first marker and reuses it only after the walk ends; load counts markers; a rehash drops markers and carries over only live keys.
- 12 keys that grow a size-12 table twice (up to 48 slots) still fit the stage at 320px, the page never scrolls sideways, slots never shift between frames, and the figure grows when both side panels collapse.
- A sequence with junk tokens, more than 12 tokens, or no valid token falls back to the variant default; a URL frame index past the new run falls back to step 1.

**Interfaces:**
- `trace.ts`: `type Scheme = "linear" | "quadratic" | "double"`; `type OpKind = "insert" | "lookup" | "delete"`; `interface Op { kind: OpKind; key: number }`; `type Cell = { state: "empty" } | { state: "full"; key: number } | { state: "marker"; key: number }`; `type OpenBadge = "Start" | "Hash" | "Probe" | "Hop" | "Place" | "Found" | "Mark" | "Not found" | "Stuck" | "Grow" | "Move" | "Switch" | "Done"`; `interface OpenEvent { badge: OpenBadge; caption: Rich; cells: Cell[]; old: Cell[] | null; oldAt: number | null; key: number | null; home: number | null; second: number | null; slot: number | null; tried: number[]; probes: number; placed: number | null; used: number }` (`cells` is the live table after the step, `old` the table being rehashed from, `oldAt` the old slot being read, `second` the second hash for double hashing, `slot` the slot examined or written this step, `tried` the slots probed so far in this walk in order (repeats kept), `placed` the slot written by `Place`, `used` the count of full plus marker slots); `type ChainBadge = "Start" | "Hash" | "Walk" | "Place" | "Found" | "Unlink" | "Not found" | "Done"`; `interface ChainEvent { badge: ChainBadge; caption: Rich; chains: number[][]; key: number | null; home: number | null; walking: number | null; walked: number; placed: number | null }` (`walking` is the index in the home chain of the item being visited, `walked` the items visited so far in this op).
- `hash.ts`: `homeOf(key: number, size: number): number` (`key mod size`); `secondOf(key: number): number` (`1 + key mod 7`); `slotAt(scheme: Scheme, key: number, size: number, i: number): number` (linear `(home + i) mod size`, quadratic `(home + i²) mod size`, double `(home + i · second) mod size`); `offsetOf(scheme: Scheme, key: number, i: number): number` (`i`, `i²`, `i · second`, the arc label); `mathsOf(key: number, size: number): string` (`"32 mod 8 = 0"`); `secondLine(key: number): string` (`"1 + 32 mod 7 = 5"`); `runsOf(cells: Cell[]): { from: number; to: number }[]` (runs of three or more consecutive full or marker slots, not wrapping).
- `open.ts`: `openRun(ops: Op[], scheme: Scheme, size: number, start?: Cell[]): OpenEvent[]`. Grammar per op: `Hash`; then for `i = 0..size-1`: `Probe` at `slotAt(i)`, and unless the walk ends, `Hop` to the next slot (no `Hop` after the last probe). A probe ends the walk when it sees the same live key (`Found`; for delete then `Mark`, which turns the slot into a marker) or an empty slot (insert: `Place` at the first marker seen in this walk, else at the empty slot; lookup and delete: `Not found`). After `size` probes with neither: insert places at the first marker if one was seen, else `Stuck`; lookup and delete end on `Not found`. A marker never matches a key and never ends a walk. The run is `Start`, every op, `Done`. Captions are plain English naming slot and key ("Slot 1 holds 8, not 32: it is taken.").

### Task 3: Resize

**Files:** Create `lib/visualizer/hash-table/resize.ts`; test `resize.test.ts`.

**Interfaces:** Consumes `openOp`, `openRun` pieces from Task 1. Produces `resizeRun(ops: Op[], size: number, threshold: number): OpenEvent[]` (linear probing). After an insert that ends on `Place` and leaves `used / size > threshold` the run emits `Grow` (`cells` is an empty table of `2 * size`, `old` the table so far, caption states the arithmetic "7 of 8 slots used is 0.88, above 0.75: build a table twice as big"), then for each full slot of `old` in index order one `Move` (`oldAt` set, `key` set, `home` the new home, chip maths `key mod newSize`) followed by that key's probes, hops and `Place` in the new table, then `Switch` (`old` null again, `size` the new size). ## Part C: the module

### Task 5: View, maths and vars

**Files:** Create `lib/visualizer/hash-table/view.ts`; test `view.test.ts`.

**Interfaces:**
- `interface ViewCtx { scheme: Scheme | "chain"; size: number; maxChain: number; threshold: number | null; meterMax: number }` (`maxChain` is the longest chain over the whole run, `meterMax` is `1` for open addressing and `max(1, ceil(final load))` for chaining, both computed once per run so the layout and meter never rescale).
- `openModelOf(ev: OpenEvent, ctx: ViewCtx): TableModel`; `chainModelOf(ev: ChainEvent, ctx: ViewCtx): TableModel`; `varsOf(ev: OpenEvent | ChainEvent, ctx: ViewCtx): VarRow[]`; `metricOf(ev, ctx): string`.
- Tones, one function for slots: the slot being probed now (`ev.slot` on `Probe`) `focus`; slots in `tried` before it `warn`; the slot of `Place`, `Found` or `Mark` `good`; the home slot before the first probe and the old slot at `oldAt` `accent`; everything else `plain`. `Done` and `Switch` clear the chip, arcs and tones. Hops: one arc from the home slot to each slot in `tried` after the first, labelled `+offsetOf(...)`, the last one `current`. The chip: `label` the key, `lines` `[mathsOf]` plus `[secondLine]` for double hashing, `to` the home slot, shown from `Hash` or `Move` until the walk ends. `runs` from `runsOf(cells)` (open addressing only). Resize: while `old` is set the model has two lists, the old one `faded` with `oldAt` accent and no chip, the new one with the chip. Marker slots are `marked`. Chaining: each slot's items are its chain; the home slot cell `accent`, visited items `outlined`, the item being visited `focus`, the newly appended item `good`; `room` is `maxChain`, `lane` false.
